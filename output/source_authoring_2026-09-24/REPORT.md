# Source-owned definition authoring — 2026-09-24

Explicit source body, field and placement edits now compile into the programs that act inside the eight-stage resident cycle. One additional explicitly bound situated operator is supported through the same implicit address relation. The native CPU/Vulkan interpreter, original31-record numerical builder, enzyme builder and original symbolic launcher are unchanged.

This closes the bounded source-to-program authoring gap identified in Unified v0.2 pp9–10,13,16. It does **not** close general source-declared application composition: the versioned builders still author the stage call plans and enzyme role wiring. Arbitrary heterogeneous selected procedures, runtime instruction synthesis, larger catalogues and optional packing remain separate work. No universality, quantum-device or physical-technology result is claimed.

Use [Dawnwood-Author.cmd](../../Dawnwood-Author.cmd) with the [usage guide](../../docs/SOURCE_PROGRAM_AUTHORING.md). The [source requirement audit](../../docs/SOURCE_AUTHORING_REQUIREMENTS.md) identifies original-document authority and the exact finite contracts.

## What changed

The compiler resolves inline `resident_binding` expressions or a registry whose declaration exactly matches the source slot. An edited body accounts for every compatible family and explicitly inherits or replaces each role. Ordered argument/output names and original guard prefixes are preserved. Custom field and placement programs retain their handles through an explicit mutation policy; common old-snapshot proposals still update their numerical anchors, radius, control and generation.

The new record supplies all three acting slot programs and all20 initial values. It has source index31..62, a separate typed family and selected role99. A45th state value carries the fifth route bit. The original64-state enzyme profile rejects that extension; no field is silently repacked. A simultaneous custom BST body is also rejected because it would need its own changed input contract.

## Execution and numerical scope

The main campaign contains28 healthy paired workloads, comparing2,134,788 instance words and350,302 committed instance-epochs per backend. Four further healthy pairs establish added-body/field/placement effects and composition with existing source edits. Four intentional failure pairs establish rollback. The mathematical campaign contains three separately labelled paired workloads; clipped diagnostic prefixes are not counted as full-cycle completion.

All recorded pairs agree in complete checkpoint bytes, not merely selected outputs. All GPU receipts report validation enabled with zero errors and warnings. These are finite measurements on the RTX5070Ti Laptop GPU, not a proof of all-device FP32 equivalence.

For the amplitude program, `d=||w||₂−1` is an exact real-arithmetic SDF in `C²=R4`; `w/(1+max(0,d))` is its Euclidean ball projection. The body uses scaled norms. The actual selected input/output prefixes contain257 lanes. Maximum component error is`1.2085e-7`; maximum projected norm is`1.0000001384`. The separate543-case expression fixture includes zero, inside, boundary, outside and scale-stress cases. Maximum component error is`1.5992e-7`, scaled SDF error`1.5542e-7`, and projected norm`1.0000002003`. All remain within the fixed tolerances declared before execution. Later phases can move amplitudes outside the ball.

The new amplitude body explicitly ignores its carrier-distance and routing-phase operands. Its carrier programs still execute in situated application and common mutation; the recorded null final-wave effect of their isolated edits is retained rather than presented as a positive coupling result. The existing Hadamard source example separately establishes full-wave field/placement dependence.

The biochemical result is consistency reconciliation, not kinetics. The source-authored proposal is evaluated against the original protected conservation-domain/projector/objective/acceptance roles. The earlier application's independent accuracy campaign does not automatically establish the same convergence rate or accuracy for a changed proposal. Exported residuals and estimated gaps retain their FP32 limitations.
