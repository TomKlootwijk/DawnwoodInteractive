# Specialization through situated definitions

Dawnwood's architectural aim is computation through fields, executable operator
records and returned state that can change those records. Specialization must
give that circulation a concrete input, allowed rule changes and checkable
output. The current headless work takes a first explicit step in the native
recurrence; it does not replace the project with a separate learning model.

## Implemented binding: finite domain constraint repair

**DWI-D1-0.1** adds four domain coordinates and one to 32 protected affine laws
to the existing C++/Vulkan equations. The laws represent equalities, halfspaces
and slabs in a declared normalized metric. Their individual fields are evaluated
without an editable body transforming the scientific coefficients.

Constraint error enters the existing geometry computation before the root body.
The actual situated mutation controller selects bounded projection relaxation.
Returned error feeds the next operator update through the ordinary state field.
The Klein transport, amplitudes, history, inverse transform and epoch ordering
remain active. This is a finite, explicitly versioned connection between domain
knowledge and the self-referential controller.

`local_lab/specialize.py` accepts an authored JSON definition and produces native
checkpoints, raw execution receipts, `result.json` and complete-population
`solutions.csv`. The [D1 campaign](../output/domain_kernel_2026-09-24/REPORT.md)
records feasible outputs in all four domains, the causal feedback connection,
controller comparisons and compute saturation. N1 hardware results remain
separately identified.

| Immediate use | Input and output contract | Boundary |
|---|---|---|
| Scientific candidate repair | Proposed quantities → assignments satisfying declared conservation/bounds | No claim to reproduce reaction kinetics or measured biology |
| Buffer constraint design | Log-activity candidates → assignments inside the authored affine conditions | Validity depends on the supplied equilibrium assumptions and coordinate model |
| Synthetic metabolic feasibility | Four flux proposals → candidates satisfying a finite authored steady-state model | No organism-wide prediction or optimal-flux objective |
| Resource-quota proposals | Four resource quantities → allocations within explicit quotas/capacities | No automatic execution of allocations, scheduler or optimal allocation claim |

The local examples are `enzyme_repair`, `buffer_design`, `metabolic_flux` and
`resource_allocation`. Their sources, parameters and assumptions are data that
must be examined, not assertions that every biochemical or engineering law has
already become a native operator.

## Acceptance before expansion

1. Confirm the compiled coordinate meaning, metric, coefficients and immutable
   law bytes.
2. Run native CPU/GPU comparison from the identical domain checkpoint, retaining
   any divergence and raw command failures.
3. Audit every final candidate against each actual packed law; return unresolved
   cases distinctly from numerical or execution failures.
4. Compare live, frozen, edited and constant controller conditions with common
   initial candidates. Determine whether feedback helps the declared task.
5. Include an incompatible-constraint case and retain its result. A finite failure
   to converge is not an unsatisfiability certificate.
6. Compare cost and output against an implementation of the same constraint
   problem before claiming a useful performance advantage.

Mutable rules may alter solver behavior; they may not move protected scientific
boundaries to manufacture success. The current cyclic relaxed projection has no
trained objective and promises neither a unique answer nor the closest feasible
point. Input scales define the distance metric, so comparisons must preserve them.

## Next native specializations

### Wider scientific constraint vocabularies

Promote a new field only with its coordinate/unit contract, real-function
definition, numerical evaluator and permitted mutation scope. Curved biochemical
equilibria, kinetic residuals and nonconvex feasible sets need different numerical
machinery; a residual is not automatically an exact signed distance. Preserve that
distinction in both the operator encoding and returned evidence.

The first extension should be one bounded task whose expected outputs can be
checked independently. Retain scientific constants while allowing identified
controller behavior to adapt. Specify failure and stopping conditions before
scaling the state population. Add an objective only if the user actually needs
optimization, and measure it separately from feasibility.

### Editable relational rule memory

A future finite target could encode three entities, two relations and a query.
It needs explicit entity and relation representations, executable composition,
direction/identity semantics and a returned derivation trace. A rule edit should
change the expected answer while preserving unrelated answers.

The present tree route is not a relational query language. Demonstrating this
specialization requires compiling and executing the relation composition inside
the substrate, not attaching labels to unrelated geometry. No relational-memory
application is claimed by the D1 affine solver.

### Local planning under protected constraints

A future planning profile needs an observation/action encoding, finite candidate
plans, immutable invariants, allowed metarule changes and an explicit result
contract. A first witness could change one resource availability and produce a
revised allowed plan, plus an unresolved outcome when no allowed plan is found.

The current resource example produces feasible numerical proposals. It does not
yet compose actions, execute external changes or establish planning competence.
That further behavior requires a versioned mapping rather than inference from
jitter or changing trajectories.

## Deeper architectural work

The source's paired-hinge composition, stronger amplitude-to-operator feedback,
full transported-frame semantics and geometric expression of more of the native
evaluator remain explicit questions. Define each new relationship and identify
the fixed evaluator that remains; do not count a larger population as a solution
to those questions.

Once a useful profile has stable semantics, a specialized hardware study can
measure its precision requirements, operations and data movement. FPGA, custom
datapath or other future implementation claims need such measurements. Native
GPU conformance alone does not establish a new physical device, general AI or
unbounded expressivity.

The practical progression is concrete: authored domain fields, protected laws,
inspectable operator-on-operator consequences, and a returned candidate whose
declared constraints can be checked independently.
