# Current literal-application acceptance audit

This audit maps the current source graph implementation to the seven conditions in [LITERAL_APPLICATION_CONTRACT.md](LITERAL_APPLICATION_CONTRACT.md). **Each condition has bounded implementation and numerical evidence.** This statement applies to the declared resident source-cycle, enzyme and authored operator/graph editions. It does not establish unrestricted source-language coverage, scientific validity of arbitrary user expressions, or a new physical computing device.

The current implementation reads the preserved source catalogue/cycle and explicit bindings, creates resident numerical definitions, and lowers the entire mutation/action graph into the generic resident CPU/Vulkan evaluator. The source-owned graph covers the original recurrence and domain composition; it is not an extra application tail attached to uneditable action wiring. See [SOURCE_GRAPH_PROGRAM.md](SOURCE_GRAPH_PROGRAM.md) for the API, commands and source-to-implementation map.

The graph-profile stress campaign and public CLI checks have completed with the receipts cited below. The [final current-source recompilation audit](../output/source_graph_2026-09-24/final_recompilation_audit.json) also passes: 14 retained cases and six matrix cases reproduce all 12,400,776 executed program bytes. Repository synchronization is the final delivery step, reported with the containing commit. Earlier-profile saturation is identified separately and is not relabeled as graph-profile saturation.

## Required work versus separate research

All seven bounded implementation acceptance conditions and their numerical, hardware, public-command and current-source provenance checks have evidence. The final recompilation audit includes source-only interventions, controls, heterogeneous routes and the separately labeled diagnostic tape. Repository synchronization delivers this coherent milestone; a failed push would remain a delivery issue. These checks do not require a new scientific or physical claim.

The bounded implementation limits remain explicit: 32 resident records, 64 FP32 state values, 256 functions/families, finite typed method sets, bounded expressions/plans and 192 live named-value registers in the graph allocator. Each GPU lane has its own state and operator records. Runtime creation of arbitrary programs, unbounded memory, arbitrary symbolic-DAG execution, shared global operator-field behavior, unrestricted cycle replacement, unimplemented BC5 packing, empirical biochemical validation and a measured advantage over conventional solvers remain separate developments. Their absence must not be concealed, but they are not silently added acceptance conditions for the finite numerical edition established here.
